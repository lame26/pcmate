# MVP 의사결정 기록

이 문서는 PC 견적 빌드업 웹앱의 MVP 범위와 주요 기술/제품 결정을 고정하기 위한 기준 문서다.
향후 상세설계서와 구현 작업은 이 결정을 우선 기준으로 삼는다.

## 1. MVP 범위

MVP는 **전체 축소 MVP**로 진행한다.

포함:
- 현재 PC 사양 입력
- 게임/작업/모니터 기반 사양 판독
- 예산 선택 입력
- 부품 후보 추천
- 카드사명 기준 단순 혜택가 계산
- 다나와 텍스트 붙여넣기 파싱
- GitHub 오픈소스 기반 다나와 크롤러 어댑터
- 최종 견적표
- 텍스트 복사
- 이미지 출력
- localStorage 저장

제외 또는 축소:
- 로그인
- DB 저장
- 고급 카드 혜택 조건 계산
- 가격 히스토리
- 가격 알림
- 공유 링크
- PDF 출력
- 커뮤니티
- 결제 연동

## 2. 가격 수집

MVP에는 다나와 가격 수집 기능을 포함한다.

크롤러는 앱 핵심 로직과 분리된 어댑터로 구현한다.
GitHub 오픈소스 크롤러를 참고하거나 래핑하되, 해당 프로젝트의 라이선스, 요청 제한, 캐시, robots.txt 준수 여부를 먼저 검토한다.

앱 레벨에서 다음 정책을 추가한다.
- 같은 pcode는 최소 6시간 재요청 금지
- 요청 실패 시 기존 캐시 반환
- 기존 캐시가 없으면 수동 입력 또는 붙여넣기 가격 데이터 사용
- 과도한 재시도 금지
- 가격 데이터에는 source, updatedAt, confidence, warnings를 반드시 포함

## 3. 카드 혜택

MVP에서는 카드사명 기준으로만 혜택가를 계산한다.

예:
- 사용자가 삼성카드를 보유한다.
- offer.cardProvider가 삼성카드다.
- 해당 offer의 benefitPrice를 내 카드 혜택가로 사용한다.

MVP에서는 다음 조건을 실제 계산하지 않는다.
- 전월 실적
- 할인 한도
- 쿠폰 중복
- 청구할인 시점
- 멤버십 적립
- 카드별 세부 상품 차이

단, 향후 확장을 위해 BenefitRule 타입은 설계에 포함한다.

## 4. 예산 입력

예산은 선택 입력으로 둔다.

예산이 있으면 후보 추천과 가격 점수에 반영한다.
예산이 없으면 게임, 작업, 모니터 조건에서 산출한 적정 티어를 기준으로 추천한다.

## 5. 빌드 모드

전체 새 PC 견적을 MVP의 기본 모드로 한다.

기존 PC 일부 업그레이드는 UX 진입점과 데이터 구조는 마련하되, MVP의 추천 흐름은 전체 견적을 우선한다.

## 6. PowerShell 사양 가져오기

PowerShell 결과 붙여넣기는 일반 텍스트와 JSON 출력을 모두 지원한다.

권장 방식은 JSON 출력이다.
일반 텍스트 파싱은 사용자가 기존 명령어 결과를 붙여넣는 경우를 위한 보조 경로로 둔다.

## 7. 게임 데이터 신뢰도

게임 데이터에는 출처, 업데이트일, 신뢰도 필드를 포함한다.

미출시 게임이나 요구 사양이 불확실한 게임은 일반 게임과 분리하고 `estimated` 상태로 표시한다.

필수 필드 예:
- source
- updatedAt
- confidence
- demandType: official | estimated | manual

## 8. 추천 로직

MVP부터 점수 기반 추천을 사용한다.

기본 점수:
- performanceFitScore
- priceScore
- compatibilityScore
- preferenceScore
- classificationScore

각 후보는 점수와 함께 reason 목록을 표시한다.
점수만 보여주지 않고, 왜 추천됐는지를 상담형 문장으로 설명한다.

## 9. 부품 등급 분류

MVP에서는 다음 수준까지 부품 등급을 분류한다.

- 칩셋/성능 티어
- 브랜드 라인 등급
- 전원부
- 쿨링
- 유통사

보증기간 기반 정밀 평가는 추후 고도화한다.

## 10. 호환성 체크

MVP 호환성 체크 범위는 다음까지 포함한다.

- CPU 소켓
- 메인보드 칩셋
- RAM 타입
- 케이스 메인보드 규격
- GPU 길이
- CPU 쿨러 높이 또는 라디에이터 호환
- 파워 용량
- 파워 GPU 보조전원 커넥터

BIOS 세부 버전, SSD 슬롯 공유, PCIe lane 구성 등은 추후 고도화한다.

## 11. 모바일 대응

MVP에는 기본 반응형 UI를 포함한다.

데스크톱 중심으로 설계하되, 모바일에서도 주요 입력과 최종 견적 확인이 가능해야 한다.

## 12. 저장 방식

MVP는 localStorage만 사용한다.

저장 대상:
- 사용자 입력
- 선택한 카드
- 선택한 게임/작업/모니터 조건
- 가격 스냅샷
- 단계별 선택 부품
- 최종 견적

JSON 내보내기, Supabase 저장, 공유 링크는 추후 개발한다.

## 13. 최종 출력

MVP 최종 견적 화면은 다음을 지원한다.

- 화면 표시
- 텍스트 복사
- 이미지 저장

PDF 출력과 공유 링크는 추후 개발한다.

이미지 출력은 브라우저 DOM 캡처 방식으로 구현한다.

## 14. 데이터 관리

MVP는 `/data/*.ts` 기반 정적 데이터로 시작한다.
하지만 Supabase 이전을 고려해 스키마형 구조로 설계한다.

모든 주요 데이터에는 다음 필드를 포함한다.

- id
- source
- updatedAt
- confidence

대상:
- Part
- GameProfile
- PriceOffer
- PriceSnapshot
- BenefitRule
- Build

## 15. 법적/정책 리스크 처리

실제 크롤러는 MVP에 포함하되, 요청 제한과 캐시를 앱 레벨에서 강제한다.

GitHub 오픈소스 크롤러에 이미 제한이 구현되어 있더라도 그대로 신뢰하지 않는다.
도입 전에 다음을 확인한다.

- 라이선스
- 요청 간격 제한
- 동일 상품 재요청 캐시
- User-Agent 설정 방식
- robots.txt 준수 여부
- 실패 시 재시도 폭주 방지
- HTML 변경 시 실패 처리
- 상업적 사용 또는 재배포 가능 여부

확인 결과 부족한 항목은 앱의 크롤러 어댑터 계층에서 보완한다.

## 16. 크롤러 실행 위치

MVP에서는 Next.js API Route에서 크롤러 어댑터를 호출한다.

추후 운영 안정성이 필요해지면 별도 worker, scheduled job, Supabase Edge Function, 또는 외부 크롤링 서비스로 분리할 수 있게 인터페이스를 유지한다.

## 17. 추천 설명 방식

추천 결과에는 점수와 reason 목록을 모두 표시한다.

예:
- 현재 목표 해상도와 주사율 기준으로 성능 여유가 적절합니다.
- 선택한 카드 기준 혜택가가 같은 티어 후보 중 낮은 편입니다.
- 선택한 케이스의 GPU 장착 길이 조건을 만족합니다.
- RGB 비선호 조건과 맞습니다.

서비스 톤은 단정형 구매 유도가 아니라 보수적이고 신뢰성 있는 상담형을 유지한다.
