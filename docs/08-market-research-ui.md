# PC 견적 빌드업 웹앱 UI 시장조사

작성일: 2026-05-12

이 문서는 PC 견적 빌드업 웹앱의 UI/UX 설계를 위한 시장조사 메모다. 목적은 경쟁 서비스를 그대로 따라 하는 것이 아니라, 사용자가 이미 익숙한 구매/견적 패턴과 현재 시장의 빈틈을 파악해 MVP 화면 설계의 판단 근거로 삼는 것이다.

## 1. 요약

PC 견적 시장의 기존 서비스는 크게 네 유형으로 나뉜다.

| 유형 | 대표 서비스 | 강점 | UI상 한계 |
| --- | --- | --- | --- |
| 가격비교/견적형 | 다나와 PC견적, 샵다나와 | 부품 카테고리, 실시간 가격, 견적/역경매 흐름 | 초보자가 “왜 이 사양인지” 이해하기 어렵고 부품 선택이 먼저 시작됨 |
| 판매/상담형 | 컴퓨존, 조립PC 전문몰 | 구매, 조립, A/S, 결제 신뢰 | 특정 판매처 중심이라 중립적 판단 도구로 보기 어려움 |
| 커뮤니티/전문가형 | 견적왕, 퀘이사존류 게시판 | 실사용자/전문가 추천, 맥락 있는 피드백 | 비정형 게시판 중심, 초보자가 질문을 잘 써야 함 |
| 글로벌 PC builder | PCPartPicker, Micro Center PC Builder, Newegg PC Builder | 호환성 체크, 저장/공유, 카테고리별 부품 선택 | 한국 카드 혜택가, 다나와 가격, 국내 쇼핑몰 맥락과 다름 |

우리 서비스의 차별화 포인트는 “부품을 먼저 고르는 도구”가 아니라 “사용자의 게임, 작업, 모니터, 카드 조건에서 적정 견적을 빌드업하는 상담형 앱”이라는 점이다.

## 2. 시장 환경

### 국내 PC 시장 흐름

IDC 코리아 보도에 따르면 2024년 국내 PC 출하량은 474만대로 전년 대비 1.1% 감소했다. 글로벌 시장이 성장한 것과 달리 국내 시장은 경기 침체와 교육 시장 축소 영향으로 회복이 약했다. 다만 AI PC, Windows 10 지원 종료, 노후 PC 교체 수요는 긍정 요인으로 언급됐다.

UI 시사점:

- 사용자는 가격과 구매 타이밍에 민감하다.
- “지금 바꿔야 한다”보다 “현재 조건에서 바꾸면 어떤 이득/리스크가 있는가”를 설명해야 한다.
- 불확실한 시장에서는 가격 갱신 시각, 신뢰도, 카드 조건 표시가 더 중요해진다.

### 2026년 가격 민감도

IDC의 2026년 전망은 메모리 공급 부족, 부품 가격 상승, 공급망 변동성을 강조한다. 아시아/태평양 PC 시장은 2025년에 성장했지만 2026년에는 부품 부족과 가격 상승으로 출하 감소가 예상된다는 분석도 있다.

UI 시사점:

- 가격 변동성을 숨기면 안 된다.
- “최저가”보다 “갱신 시각이 있는 조건부 가격”으로 보여줘야 한다.
- 가격 데이터 부족, 캐시 사용, 크롤링 실패를 정상 상태로 설계해야 한다.

## 3. 경쟁 서비스 관찰

### 다나와/샵다나와

관찰 내용:

- 다나와는 PC견적을 별도 주요 서비스로 제공한다.
- 샵다나와는 실시간 PC견적, PC견적, 역경매, 조립PC, 무이자PC, 중고PC, 구매상담 등을 같은 생태계 안에 둔다.
- 역경매는 소비자가 견적을 구성하고 판매자들이 입찰하는 구조다.
- 샵다나와 페이지에는 실시간 견적 요청, 평균가, 입찰수, 진행상태가 노출된다.

강점:

- 가격/상품 데이터 기반이 강하다.
- 사용자는 실제 구매로 이어질 수 있다.
- 부품 카테고리와 견적 흐름이 시장 표준에 가깝다.

약점 또는 빈틈:

- 사용자가 부품을 고를 줄 알아야 한다.
- “게임/작업/모니터 조건에서 왜 이 사양인지”가 화면의 출발점은 아니다.
- 가격은 강하지만 상담형 사양 판독은 상대적으로 약하다.

우리 UI 적용:

- 부품 카테고리 순서와 견적 결과 구조는 익숙한 패턴을 참고한다.
- 첫 화면은 가격표가 아니라 “내 조건 입력”에서 시작한다.
- 다나와 가격은 결과 근거로 사용하되, 서비스 정체성을 다나와 대체재로 만들지 않는다.

### 컴퓨존류 판매/상담형 서비스

관찰 내용:

- 컴퓨존의 “깎아줘 PC”는 타 사이트 견적 캡처를 첨부해 가격 제안을 받는 흐름을 제공한다.
- 조립PC 구매 예정 고객, 결제 기한, 증빙자료, 조립비, 주문 조건 등 구매 전환 중심 조건이 명확하다.

강점:

- 판매처 신뢰, 결제, 조립, A/S로 이어진다.
- 사용자는 견적 이후 실제 주문까지 진행할 수 있다.

약점 또는 빈틈:

- 특정 판매처 중심이다.
- 사용자가 이미 견적서를 갖고 있다는 전제가 있다.
- 중립적 사양 진단보다 구매 상담/가격 제안에 가깝다.

우리 UI 적용:

- MVP는 결제/판매를 하지 않으므로 구매 버튼처럼 보이는 CTA를 피한다.
- 최종 견적은 “주문서”가 아니라 “검토 가능한 견적표”로 표현한다.
- 카드 혜택과 가격은 “예상 금액”임을 계속 노출한다.

### 견적왕/커뮤니티형 견적 서비스

관찰 내용:

- 견적왕은 전문가 추천, 커뮤니티 기반 신뢰, 특정 부품 이슈 회피를 전면에 둔다.
- “AS, 이슈 부품 배제”처럼 초보자가 신뢰하고 싶어 하는 요소를 강조한다.

강점:

- 사람이 골라주는 느낌이 강하다.
- 단순 스펙보다 실전 이슈와 평판을 반영한다.

약점 또는 빈틈:

- 추천 기준이 구조화된 데이터로 보이기 어렵다.
- 사용자가 자신의 조건을 바꿨을 때 결과가 어떻게 변하는지 즉시 보기 어렵다.

우리 UI 적용:

- 추천 이유를 사람 말처럼 쓰되, 데이터 필드와 warning으로 구조화한다.
- “이슈 가능성”, “정보 부족”, “가격 신뢰도 낮음” 같은 경고를 배지와 문장으로 함께 제공한다.

### PCPartPicker

관찰 내용:

- PCPartPicker는 가격 비교와 호환성 중심 PC builder의 글로벌 표준에 가깝다.
- 빌드 리스트 저장, 공유, 가격 추적, 부품 호환성 확인, 빌드 가이드 같은 흐름이 핵심이다.

강점:

- 부품 리스트를 만드는 사용자의 반복 작업을 잘 지원한다.
- 호환성 경고와 공유성이 강하다.
- 커뮤니티 피드백과 빌드 저장이 자연스럽다.

약점 또는 빈틈:

- 사용 목적에서 사양을 역산하는 상담형 UX는 핵심이 아니다.
- 한국 쇼핑몰, 다나와 가격, 카드 혜택가 맥락과 다르다.

우리 UI 적용:

- 부품 간 호환성 경고와 최종 견적 공유 형식은 참고한다.
- MVP에서는 공유 링크가 제외되므로 텍스트 복사와 이미지 저장을 더 신뢰감 있게 만든다.
- 추천은 “부품 선택 후 호환성 확인”이 아니라 “조건 입력 후 후보 제안”으로 차별화한다.

### Micro Center PC Builder

관찰 내용:

- Micro Center PC Builder는 부품 선택, 저장, 공유, 출력, 장바구니/매장 픽업과 연결된다.
- FAQ에서는 PC builder가 주요 부품 호환성을 자동 확인한다고 설명한다.
- 완성 후 Reddit, 커뮤니티, HTML/text/markdown 형식 공유가 가능하다고 안내한다.

강점:

- 선택, 저장, 공유, 구매 연결이 명확하다.
- 초보자에게 CPU/GPU부터 시작하는 가이드를 제공한다.
- 오프라인 매장/조립 서비스와 연결된다.

약점 또는 빈틈:

- 보유 카드 혜택, 국내 가격 파싱, 다나와 기반 최저가 맥락이 없다.
- 매장 재고와 구매 전환 중심이다.

우리 UI 적용:

- 최종 견적 텍스트 복사는 Markdown에 가까운 읽기 좋은 포맷으로 설계한다.
- 저장/복구는 localStorage 기반으로 명확히 표현한다.
- 구매 연결이 없으므로 “장바구니” 같은 단어를 MVP에서는 피한다.

### Newegg PC Builder

관찰 내용:

- Newegg PC Builder는 호환 부품을 보여주는 온라인 configurator로 소개된다.
- 동시에 Newegg는 실제 호환성은 제조사 정보와 다를 수 있으며 보증하지 않는다는 고지를 둔다.

강점:

- 부품 선택 단계에서 호환성 필터를 제공한다.
- 구매몰의 상품 데이터와 직접 연결된다.

약점 또는 빈틈:

- 호환성 보장 범위에 대한 고지가 필요하다.
- 몰 종속성이 강하다.

우리 UI 적용:

- 호환성 체크도 “판단 보조”라는 점을 명확히 표시한다.
- critical warning과 확인 필요 warning을 구분한다.
- 제조사 세부 스펙 확인이 필요한 경우를 숨기지 않는다.

### Can You RUN It / System Requirements Lab

관찰 내용:

- Can You RUN It은 13,000개 이상의 게임 요구 사양 DB를 제공한다고 안내한다.
- 사용자의 PC 사양을 감지해 게임 실행 가능 여부를 확인하는 흐름이 핵심이다.

강점:

- “내 PC가 이 게임을 돌릴 수 있나?”라는 질문에 바로 답한다.
- 게임 중심 사용자의 진입 장벽이 낮다.

약점 또는 빈틈:

- 실행 가능 여부 중심이지, 새 PC 견적 빌드업과 가격 비교는 핵심이 아니다.
- 해상도, 주사율, 옵션, 멀티태스킹, 카드 혜택가까지 연결되지 않는다.

우리 UI 적용:

- 게임 선택은 장르보다 게임명 중심이 적합하다.
- 단순 실행 가능 여부 대신 목표 옵션/주사율/모니터 조건을 함께 받는다.
- “가능/불가능”보다 “적정 티어, 병목 가능성, 과투자 가능성”을 보여준다.

## 4. 사용자 문제 정의

시장조사 기준으로 사용자의 핵심 문제는 다음이다.

1. 부품을 먼저 고르라고 하면 시작이 어렵다.
2. 견적 사이트는 많지만 “내 용도에 맞는 적정선”을 설명해주는 곳은 부족하다.
3. 가격은 많지만 카드 혜택, 배송비, 조건부 할인, 갱신 시각이 섞여 실제 체감가가 헷갈린다.
4. 커뮤니티 조언은 유용하지만 질문 작성과 답변 해석이 어렵다.
5. 해외 builder의 호환성 UX는 좋지만 한국 구매 환경과 맞지 않는다.
6. 기존 PC 일부 재사용은 매력적이지만 초보자는 호환성 리스크를 알기 어렵다.

## 5. 포지셔닝 제안

### 한 줄 포지션

PC 견적 빌드업 웹앱은 “부품을 고르는 가격표”가 아니라, 사용자의 게임·작업·모니터·카드 조건에서 적정 견적을 단계적으로 설명해주는 상담형 견적 도구다.

### 경쟁 구도상 위치

| 축 | 기존 가격비교 서비스 | 커뮤니티 상담 | 해외 PC builder | 우리 서비스 |
| --- | --- | --- | --- | --- |
| 시작점 | 부품/카테고리 | 질문글 | 부품 선택 | 사용 조건 |
| 강점 | 가격/상품량 | 사람의 조언 | 호환성/공유 | 사양 판독+가격 신뢰도 |
| 사용자 난이도 | 중간~높음 | 높음 | 중간 | 낮음~중간 |
| 구매 연결 | 강함 | 약함 | 중간~강함 | MVP에서는 없음 |
| 신뢰 장치 | 쇼핑몰/입찰 | 전문가/댓글 | 호환성 체크 | reason, warning, confidence |

## 6. UI 기회

### 1. 부품 선택 전 “조건 요약”을 만든다

경쟁 서비스는 대체로 CPU, 메인보드, GPU 선택에서 시작한다. 우리 서비스는 사용 조건을 먼저 받고 다음 요약을 만든다.

- 주력 게임
- 목표 해상도/주사율
- 작업/멀티태스킹 조건
- 예산 유무
- 카드 혜택 적용 가능성
- 추천 사양 티어
- 과투자/병목/정보 부족 경고

### 2. 추천을 점수보다 문장으로 설득한다

초보자는 점수보다 “왜 이 정도면 충분한지”를 더 필요로 한다. 후보 카드에는 다음 순서를 권장한다.

1. 후보 역할: 절약형, 추천형, 상급형
2. 실결제 예상가
3. 추천 이유 2~3개
4. 주요 warning
5. 세부 점수와 데이터 출처

### 3. 가격 신뢰도는 기본 UI에 포함한다

가격 정보는 다음을 한 묶음으로 보여줘야 한다.

- 일반 최저가
- 내 카드 혜택가
- 배송비 포함 여부
- 적용 카드
- 갱신 시각
- confidence
- warnings

### 4. “모름”을 정상 입력으로 취급한다

초보자는 CPU, 메인보드, 파워 정보를 모를 수 있다. 경쟁 서비스가 부품명을 요구할수록 사용자는 이탈한다. 우리 서비스는 모르는 값을 unknown으로 받아들이고, 결과에서 신뢰도와 보정 요청으로 처리해야 한다.

### 5. 최종 견적은 공유용 문서처럼 보여야 한다

MVP에는 공유 링크와 PDF가 없다. 따라서 최종 화면의 텍스트 복사와 이미지 저장 품질이 중요하다.

추천:

- 텍스트 복사는 커뮤니티/메신저에 붙여넣기 쉬운 구조
- 이미지 저장은 별도 출력용 레이아웃
- 가격 조건과 주의사항을 이미지에도 포함

## 7. 화면별 시장조사 반영 포인트

| 화면 | 시장에서 배운 점 | 적용 방향 |
| --- | --- | --- |
| 홈 | 기존 서비스는 가격/견적 진입이 강함 | 랜딩 설명보다 `내 조건으로 견적 만들기`를 최우선 |
| 카드 선택 | 국내 구매는 카드 조건이 중요함 | 카드 혜택은 단순 계산이며 조건부임을 명시 |
| 현재 사양 입력 | 자동 감지 서비스는 편하지만 신뢰/보안 우려가 있음 | PowerShell 붙여넣기와 수동 보정 중심 |
| 게임 선택 | 게임 실행 가능 여부 서비스 수요가 존재 | 게임명 중심, 목표 옵션/주사율까지 입력 |
| 사양 판독 | 기존 견적 서비스의 빈틈 | 적정 티어, 병목, 과투자, 신뢰도 표시 |
| 가격 수집 | 다나와 가격 생태계가 강함 | 다나와 텍스트/pcode를 보강 데이터로 사용 |
| 빌더 | 해외 builder는 호환성 UX가 강함 | 단계별 후보와 호환성 warning을 병행 |
| 최종 견적 | 커뮤니티 공유와 검토 니즈가 큼 | 텍스트 복사/이미지 저장을 깔끔하게 제공 |

## 8. MVP 우선순위 제안

### 반드시 해야 할 것

- 조건 입력 기반 사양 판독
- 추천 이유와 warning
- 가격 confidence와 updatedAt
- 카드 혜택가 조건부 안내
- localStorage 저장/복구
- 텍스트 복사와 별도 출력용 이미지
- 모바일 주요 입력/최종 확인

### MVP에서 밀어도 되는 것

- 계정 기반 저장
- 커뮤니티 공유 링크
- PDF 출력
- 완전한 가격 히스토리
- 카드별 상세 상품 조건 계산
- 고급 성능 차트
- 다크모드

## 10. UI 결론

이 시장에서 가장 큰 빈틈은 “가격표와 부품 리스트는 많지만, 내 사용 조건에서 왜 이 견적이 적정한지 설명하는 중립적 앱”이다.

따라서 UI는 다음 원칙을 유지해야 한다.

1. 홈은 랜딩페이지가 아니라 앱 시작 화면이다.
2. 부품 선택보다 사용 조건 입력이 먼저다.
3. 추천 결과는 점수보다 이유와 경고가 먼저 읽혀야 한다.
4. 가격은 항상 조건부 데이터로 표시한다.
5. 최종 견적은 구매 주문서가 아니라 검토 가능한 상담 결과물이다.
6. 다나와/컴퓨존/PCPartPicker를 대체한다고 말하지 말고, 그 전 단계의 판단 보조 도구로 자리 잡는다.
