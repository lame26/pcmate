# Feature Backlog

이 문서는 현재 진행 중인 구현 작업과 분리해서, 추후 추가하거나 개선하고 싶은 기능 아이디어를 기록하는 공간이다.

## 사용 방법

- 아직 확정되지 않은 아이디어도 자유롭게 적는다.
- 구현 중인 작업 To-do와 섞지 않는다.
- 기능이 구체화되면 `docs/04-feature-design.md` 또는 구현 이슈로 옮긴다.
- 우선순위는 `P0`, `P1`, `P2`, `Later` 중 하나로 둔다.

## 상태

- `idea`: 아이디어만 있는 상태
- `research`: 검토/자료 조사 필요
- `design`: UX 또는 로직 설계 필요
- `ready`: 구현 가능할 정도로 정리됨
- `done`: 반영 완료
- `hold`: 보류

## 메모

### 입력/설문 UX

- 빌더에서는 “다음 부품 선택”과 “최종 견적 보기”를 분리한다.
- 필수 카테고리가 덜 선택된 상태라면 최종 견적 CTA를 비활성화하거나 “아직 7개 부품 남음”처럼 명확히 표시한다.

### 추천 로직

- 후보를 3개로 고정하지 말고 조건에 맞는 후보를 더 보여준다.
- 첫 번째 후보는 추천/자동 선택 후보로 강조하고, 나머지는 비교 선택지로 제공한다.
- 후보 확장 시 blocked 후보는 제외하고, needs-check 후보는 별도 배지로 구분한다.

### 호환성/안전성

- “조건 확인 필요”를 단순 문구로 끝내지 말고, 어떤 부품 조합에서 왜 확인이 필요한지 부품별로 보여준다.
- 다나와 호환성 체크처럼 CPU-보드, 보드-RAM, GPU-케이스, 쿨러-케이스, PSU-GPU 등을 행 단위로 표시하는 화면을 검토한다.
- 호환성 체크 상세 팝업 또는 전용 패널을 제공한다.
- 웹이 대신 판단할 수 있는 항목은 최대한 pass/blocked로 판단하고, 정말 데이터가 부족한 항목만 needs-check로 남긴다.

### 가격/다나와 데이터

- 일반 최저가와 혜택 최저가를 분리 표시한다.
- 사용자가 보유한 카드와 일치하는 혜택가만 “내 혜택가”로 강조한다.
- 혜택 조건 원문, 카드사, 쇼핑몰, 배송비, 가격 갱신 시각을 같이 보여준다.

### 최종 견적/공유

- 여러 견적을 저장하고 전환할 수 있어야 한다.
- 현재 견적 초기화 기능이 필요하다.
- 견적 복제 후 예산/부품만 바꾸는 비교 흐름을 지원한다.
- 최종 견적 화면에서 부품별 일반가/혜택가/배송비를 분리한다.

### 고급 사용자 기능

- RAM/SSD 등 동일 카테고리 부품을 여러 개 또는 여러 세트 추가할 수 있게 한다.
- RAM은 같은 세트 추가와 다른 세트 혼용을 구분해야 한다.
- SSD는 OS용/게임용/작업용 등 용도 라벨을 붙일 수 있으면 좋다.
